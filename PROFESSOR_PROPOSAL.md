# AWS Project Proposal — 254 Mass Connect

**Proposed title:** Design and Implementation of an AWS-Hosted Community Events and Photo-Sharing Web Application

**Purpose.** 254 Mass Connect is a community of Kenyan youth and friends in Massachusetts who connect through events such as shared meals, games and future cookouts or road trips. One practical issue we've encountered is that photos distributed through WhatsApp may be compressed, making it harder for members to keep original-quality memories. The proposed application will provide one place to learn about activities, express interest in joining, and browse event albums with original-file downloads.

**Current status (November 15, 2026).** All four pages are implemented locally. DynamoDB and S3 adapters are not implemented; no AWS deployment is verified. Join submissions and RSVPs currently use local JSON files. The Gallery catalog is empty following withdrawal of personal-photo publication approval; Home and Join use photo-free placeholders. The following cloud behavior is proposed, not completed.

**Proposed application scope for Fall 2026.** Four responsive pages: Home, Upcoming Events, Photo Gallery, and Join Us. The Join Us form sends validated information to a Node.js API running on Amazon EC2, which saves the submission to Amazon DynamoDB. The photo gallery displays selected approved event images, with original files retained privately in Amazon S3 and time-limited download links generated by the EC2 backend. Photo publication will remain administrator-controlled: an authorized maintainer verifies consent, supplies approved files and updates metadata manually; no upload portal or admin dashboard is included. Event entries will initially be maintained directly in the application's content, rather than through a separate administration system.

**Proposed AWS architecture (subject to final implementation).** Route 53 for DNS, CloudFront for website delivery, EC2 for Nginx/React/Node.js, IAM roles and a reviewer account, DynamoDB for form submissions, S3 for photo files, Systems Manager for remote administration, and CloudTrail for activity auditing. CloudWatch and SNS will demonstrate a triggered operational alert; AWS Budgets will provide spending notifications. This proposes eleven services including Route 53. The intended course grouping is eight Tier 1 services (EC2, IAM, S3, DynamoDB, CloudFront, Route 53, Systems Manager, CloudTrail) and three Tier 2 services (CloudWatch, SNS, AWS Budgets), subject to confirmation with Professor Bob Bell for MSIT.5650 at UMass Lowell. A standard VPC, security group, public subnet and Internet Gateway will be configured, but not counted toward the service minimum.

**Planned demonstrations.** (1) Browser form → EC2 backend → DynamoDB record; (2) EC2 uses its IAM role to issue an S3 download link and return the original photo unchanged; (3) CloudWatch alarm is triggered deliberately and notifies an SNS email subscription; (4) Systems Manager accesses EC2 without opening public SSH; (5) resource visibility is verified using the required IAM professor reviewer account; (6) billing thresholds, architecture, service interaction and troubleshooting are documented.

**Project constraints.** The initial application excludes payment collection, member accounts, facial recognition, and administrator dashboards. Example photos and fictional test registrations will be used unless the people pictured have approved public sharing. The estimated project spend will be monitored with AWS Budgets. A lifecycle policy for original photographs (Standard, then optional Standard-IA, then expiration) will be configured if it can be tested and described accurately within the schedule.

**Question for approval.** Would this four-page EC2-based application, demonstrating the proposed AWS services and their interactions, be appropriate for the Fall 2026 project? I plan to focus the report on AWS configuration, service integration, monitoring, security, evidence of testing, and lessons learned rather than building a complex social media application.
